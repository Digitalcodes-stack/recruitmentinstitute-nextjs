━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  FILES AFFECTED : 23 tsx files across entire project

  EXACT ERROR:
  ────────────
  "Event handlers cannot be passed to Client Component props.
   <div style={{...}} onMouseEnter={function onMouseEnter} onMouseLeave=...>
   If you need interactivity, consider converting part of this to a Client Component."
  at stringify (<anonymous>:1:18) — Next.js 16.2.7 Turbopack

  ROOT CAUSE:
  ────────────
  Next.js 16.2.7 with Turbopack introduced stricter serialization checks at the
  server→client component boundary. Even though all affected files had 'use client'
  at the top, Turbopack was incorrectly flagging inline arrow function event handlers
  (onMouseEnter/onMouseLeave) on DOM elements during its static analysis pass.
  This is a known Turbopack 16 quirk — the serializer treats these as potentially
  non-serializable across the boundary.

  FIX APPROACH — Automated script + CSS class-based hover:
  ─────────────────────────────────────────────────────────
  Step 1: Wrote a Node.js script that:
    • Walked all .tsx files in the project (excluding node_modules, .next)
    • Found every file containing 'onMouseEnter' or 'onMouseLeave'
    • Stripped all onMouseEnter={...} and onMouseLeave={...} props
    • Used brace-depth tracking to correctly handle multi-line arrow functions
    • Preserved all surrounding JSX structure intact

  Step 2: For ChatAssistant.tsx specifically, replaced the JS-driven hover
  with CSS class-based hover rules in the injected <style> tag:
    .ec-wa-btn:hover      { transform: scale(1.1) }
    .ec-chat-btn:hover    { transform: scale(1.08) }
    .ec-option-bot:hover  { border-color: #1E40AF; transform: translateY(-2px) }
    .ec-option-expert:hover { border-color: #D97706; transform: translateY(-2px) }
    .ec-need-btn:hover    { border-color: #6366F1; background: #F8FAFC }
    .ec-connect-btn:hover { transform: translateY(-1px) }
