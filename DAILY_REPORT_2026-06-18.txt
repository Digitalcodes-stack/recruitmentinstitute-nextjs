================================================================================
  PART 2 - IMPLEMENTATION (SPRINTS 1-5)
================================================================================

SPRINT 1 - Trainer Management
   Schema:
     - Added Trainer model (trainers table) with login credentials.
     - Extended AuthSession.type with 'trainer'.
   Database:
     - Synced via `prisma db push` (project has no migration history; this
       matches the existing workflow). No data loss - confirmed before
       running.
   API:
     - Full CRUD: src/app/api/admin/trainers/route.ts (+ [id]/route.ts),
       with bcrypt password hashing on create/update.
     - Login: src/app/api/auth/trainer/login/route.ts, reusing the existing
       JWT + cookie session machinery (same pattern as student/membership).
   Admin UI:
     - /admin/trainers (list with active/inactive badges), /new, /[id]/edit.
     - components/admin/TrainerForm.tsx, TrainerActions.tsx.
   Wiring:
     - Added "Trainers" to the admin sidebar (People group) and a stat card
       on /admin/dashboard.

SPRINT 2 - Batch / Session / Enrollment / Attendance (V1 MVP core)
   Schema:
     - Added Batch, Enrollment, Session, Attendance models plus BatchMode,
       BatchStatus, EnrollmentStatus, SessionStatus enums.
   API:
     - Batch CRUD: /api/admin/batches (+ [id]).
     - Session CRUD: /api/admin/sessions (+ [id]), filterable by batchId,
       with a plain meetLink string field (manual paste, per PDF V1; later
       swappable for automated Meet creation behind the same field).
     - Enrollment: /api/admin/enrollments (+ [id]) - enforces batch capacity
       and prevents duplicate enrollment.
     - Student-facing: POST /api/sessions/[id]/join - verifies enrollment,
       returns the Meet link, upserts an Attendance row with joinedAt/
       present (click-to-join attendance per PDF Module 14).
   Admin UI:
     - /admin/batches (table list with student/session counts, status
       badges), /new, /[id]/edit, and /admin/batches/[id] - a batch
       dashboard to enroll students and add sessions with an inline,
       manually-pasted Meet link.
     - components/admin/BatchForm.tsx, BatchActions.tsx, BatchDetail.tsx.
   Wiring:
     - New "Training" sidebar group; Batches stat card on the dashboard.

SPRINT 3 - Reminder Engine (JobQueue + Cron + Email)
   Schema:
     - Added JobQueue model (job_queue table), indexed on (status, runAfter)
       for the polling hot path. This replaces the originally-specified
       Celery/RabbitMQ stack with an in-database queue, per the "stay in
       Next.js/Prisma" decision.
   Email:
     - lib/email.ts: added sendSessionReminderEmail (24h / 1h / 15m lead
       times).
   Jobs:
     - lib/jobs/sendReminder.ts - fans out to all ENROLLED students in a
       session's batch, skips cancelled sessions.
     - lib/jobs/queue.ts - enqueueSessionReminders / cancelSessionReminders,
       computes the three reminder run-times from a session's start time.
     - Wired into session create (enqueue), update (reschedule on time
       change, cancel on CANCELLED status), and delete (cancel pending jobs).
   Cron:
     - POST /api/internal/cron/tick - transactionally claims due pending
       jobs (prevents double-processing), dispatches by job type, retries
       up to 3 times with a 5-minute backoff before marking failed.
     - vercel.json added with a */5 * * * * schedule.
     - CRON_SECRET documented in .env.example (Vercel auto-sends it as a
       Bearer token on cron-triggered requests).

SPRINT 5 - Student & Trainer Dashboards (built before Sprint 4 by request)
   Student side:
     - Extended /profile (existing page) to query the logged-in student's
       enrollments (batch -> course/trainer/sessions, plus attendance) and
       render a new "My Training" section.
     - components/site/StudentTrainingPanel.tsx - upcoming sessions with a
       "Join Class" button (calls the join/attendance endpoint, then opens
       the Meet link), completed sessions with present/not-marked status,
       and a per-batch attendance percentage badge.
   Trainer side:
     - New (trainer) route group (pass-through layout, mirroring the
       existing (admin) group's pattern).
     - /trainer-login - dedicated login page (components/trainer/
       TrainerLoginClient.tsx) posting to /api/auth/trainer/login.
     - /trainer/dashboard - stat cards (assigned batches, total students,
       upcoming sessions) plus "My Batches" and "Upcoming Sessions" panels
       with Meet-link status, scoped to the logged-in trainer only.
     - components/trainer/TrainerLayout.tsx - lightweight header/logout
       chrome for the trainer portal.

SPRINT 4 - LMS Curriculum (Module -> Chapter -> Topic -> Lesson -> Resource)
   Schema:
     - Added Module, Chapter, Topic, Lesson, Resource, LessonProgress models
       (6 new tables) cascading from Course; LessonType and ResourceType
       enums. Resource can attach to either a Lesson or a Session, so live-
       session materials reuse the same model later.
   Admin API:
     - Full CRUD for all four curriculum levels: /api/admin/modules,
       /chapters, /topics, /lessons, plus /api/admin/lms-resources.
     - Single nested-fetch endpoint /api/admin/courses/[id]/curriculum to
       avoid 4 round-trips from the builder UI.
   Admin UI:
     - components/admin/CurriculumBuilder.tsx - collapsible 4-level tree
       with inline add/delete at every level and resource attachment per
       lesson.
     - New /admin/courses/[id]/curriculum page, reachable via a new
       "Curriculum" button added to each course row in /admin/courses
       (components/admin/CourseActions.tsx).
   Student API:
     - /api/student/courses/[id] - enrollment-gated nested curriculum fetch.
     - /api/lms/progress - mark a lesson complete/incomplete; access is
       checked by walking Lesson -> Topic -> Chapter -> Module -> Course and
       confirming the student has an enrollment in that course.
   Student UI:
     - components/site/CoursePlayer.tsx - sidebar curriculum tree with
       progress checkmarks and a percent-complete bar; main pane renders
       video (iframe embed), rich text, or resource downloads depending on
       lesson type, with a "Mark Complete" toggle.
     - New /profile/courses/[id] page; linked from the course title inside
       StudentTrainingPanel on /profile.
