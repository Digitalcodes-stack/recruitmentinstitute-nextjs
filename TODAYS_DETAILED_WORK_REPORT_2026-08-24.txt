2. ISSUES IDENTIFIED & ROOT CAUSES
====================================================================================================
Issue A: "Login details from LOGIN_CREDENTIALS.txt not working on server"
  - Root Cause: The cloud database was originally empty/unmigrated with missing tables and dummy accounts,
    causing Prisma queries to fail with 500 / 401.

Issue B: "React Hydration Error #418 & 404 errors on terms/privacy"
  - Root Cause: Missing route handlers for `/terms` and `/privacy` caused client-side prefetch 404s.
    Client/server copyright year rendering caused React #418 hydration mismatch.

Issue C: "When clicking Take Assessment, it goes back to login page"
  - Root Cause 1: User signed into `/candidate-login` with Priya Sharma (`priya.sharma@gmail.com`),
    which was stored in `login_student`. The candidate endpoint returned 401 Unauthorized.
  - Root Cause 2: `/profile/assessments/take/[courseId]` checked `session.type !== 'student'` and
    redirected unauthenticated users to login.
  - Root Cause 3: Next.js candidate logout had hardcoded fallback `http://localhost:3000`.

Issue D: "This portal is for approved student accounts only / Inactive accounts"
  - Root Cause: In the migrated database, several students had `status = false` (inactive) and
    candidates had `accept_signin = 0` (unapproved), blocking portal access.

Issue E: "FastAPI request failed (HTTP 503)"
  - Root Cause: The FastAPI Cloud Run service was failing its startup readiness probe due to an Alembic
    migration version mismatch (`0010_add_question_metadata_fields` vs `0010`) and outdated container image.
