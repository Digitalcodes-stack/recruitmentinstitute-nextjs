## 2. STRUCTURAL LAYOUT FIXES (`src/app/globals.css`)

- **The "Left-Alignment" Bug:** A global structural issue was causing specific sections (like the "No.1 Recruitment Training Institute" heading) to flush completely to the left side of the screen rather than staying centered.
- **Root Cause Analysis:** Tailwind CSS v4 introduces a built-in `container` class that forcefully applies `width: 100%` but completely omits centering (`margin: 0 auto`) and padding. This internal utility was overriding our custom `.container` styles.
- **Technical Resolution:**
  1. Intercepted the Tailwind v4 theme engine by injecting `--container-*: initial;` inside the `@theme` block in `globals.css`, effectively disabling the native container module.
  2. Completely rewrote the `.container` class with immutable standard CSS:
     ```css
     .container {
       width: 100%;
       max-width: 80rem; /* 1280px */
       margin-left: auto;
       margin-right: auto;
       padding-left: 1.5rem;
       padding-right: 1.5rem;
     }
     ```

## 3. DEVELOPMENT ENVIRONMENT & CACHING PIPELINE

- **Hydration Mismatch Errors:** Next.js and Turbopack exhibited highly aggressive caching behavior. Changes made to `HomePage.tsx` and `globals.css` were not reflecting in the browser, causing server-to-client hydration mismatches (the server returned the new HTML, but the browser was serving stale JavaScript from disk cache).
- **Hard Reset Protocol Executed:**
  - Wrote multi-stage PowerShell termination commands (`Get-Process -Name node | Stop-Process -Force`) to forcefully sever lingering active Node instances.
  - Recursively deleted `.next` and `node_modules/.cache` to destroy the Turbopack build cache.
  - Dynamically migrated the Next.js development server across sequential ports (`3001` -> `3003` -> `3004`) to completely bypass the browser's persistent HTTP/Local cache and force a 100% fresh DOM render.

## 4. DATABASE INITIALIZATION & PRISMA ORM (BACKEND)

- **Database Authentication Failure (P1000):** When navigating to `/blogs`, Prisma threw an authentication error against `localhost:5432`.
  - **Fix:** Discovered that the `.env` file contained placeholder credentials (`postgresql://postgres:password@...`). Verified with the user and successfully updated the connection string to use the correct local password (`postgres:postgres`).
- **Database Non-Existent Error (P1003):** Post-authentication, Prisma reported that the `recruitmentinstitute` database did not exist.
- **Prisma Schema & Config Repair (v7.x Compatibility):**
  - Attempting to run `npx prisma db push` threw a validation error (`P1012`) because the `url` property is deprecated inside `datasource` blocks in the latest Prisma v7 engine.
  - **Action:** Removed `url` from `prisma/schema.prisma`.
  - Discovered that `prisma.config.ts` was not auto-loading environment variables.
  - **Action:** Imported `dotenv` and injected `dotenv.config()` into `prisma.config.ts`, directly mapping `process.env.DATABASE_URL` to the datasource configuration.
- **Successful Schema Synchronization:** Executed `npx prisma db push`. The command successfully provisioned the `recruitmentinstitute` database in PostgreSQL and synchronized the entire table architecture (AdminUser, User, Course, Blog, etc.). The `/blogs` page now operates seamlessly.
